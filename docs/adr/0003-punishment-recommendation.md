# ADR 0003: Ориентир по основному наказанию

Рекомендация строится по обстоятельствам дела. Отдельное поле для проекта наказания в интерфейсе не требуется. API сохраняет возможность формальной проверки черновика для прежних клиентов.

В расчёт входят сопоставимые дела той же части ст. 290 с одинаковыми процессуальными условиями. Одно дело учитывается один раз. Для корпуса с проверенными числовыми признаками используется структурный kNN. Если таких признаков нет, используются совпавшие по части статьи и условиям дела. Учитываются однозначно определённые основные наказания. Для каждого вида с достаточной поддержкой показываются медиана и интервал между первым и третьим квартилями. При равной поддержке выводятся оба варианта, при недостатке наблюдений отображается причина.

Текущий текстовый индекс и числовые признаки старой выгрузки строились по полным приговорам, поэтому могут содержать сведения о наказании. Они используются для просмотра похожих дел. Расчёт опирается на подготовленные числовые признаки, если они доступны. Для включения текста в расчёт нужен отдельный индекс по сведениям, доступным до решения, и проверка качества поиска.

Исторический интервал описывает выборку. Правовые санкции зависят от применимой редакции УК, индивидуальных обстоятельств и правил назначения основных и дополнительных наказаний. Пока автоматическая проверка этих ограничений имеет статус `not_checked`. Обоснование строится из проверяемых счётчиков и правил расчёта. Генеративная модель не требуется.

# ADR 0001: модельные backend-решения для MVP

Дата: 2026-11-08
Статус: принято для MVP; retrieval backend подлежит замене по результатам benchmark

## Контекст

Система должна работать локально с русскими судебными текстами. До разметки пар
«приговор → апелляция» нельзя обучить и откалибровать классификатор риска. Генеративный
объяснитель Qwen в текущий контур не входит. Доступная GPU — RTX 3060 12 ГБ, но текущая
локальная сборка PyTorch использует только CPU.

## Решение

### Encoder для NER и последующих классификаторов

- Модель: `deepvk/RuModernBERT-base`.
- Ветка: `patched-tokenizer`.
- Закреплённая ревизия: `8aee6f818db9070b635a549580dc64dcfa03e39a`.
- Лицензия: Apache-2.0.
- Назначение базовых весов: representations и последующее обучение отдельных голов.

Smoke-test на CPU (Transformers 5.14.1, PyTorch 2.13.0+cpu) выполнен: выход `[1, 11, 768]`,
все значения конечные, `trust_remote_code=False`. Эффективный config содержал
`local_attention=256` при `sliding_window=128`; это закрепляется как свойство проверенной среды,
а не как неизменная характеристика всех версий библиотек.

Базовый MLM checkpoint не выдаёт вероятность апелляционного риска. До обученного и
независимо проверенного checkpoint API возвращает `appeal_risk.status=unavailable` и
`score=null`.

### Dense retrieval

Два равноправных кандидата, а не заранее объявленный победитель:

- `ai-sage/Giga-Embeddings-instruct-480M-0826`, ревизия
  `1763d603adac8057bd6482a708001b0ed2e0a903`, MIT;
- `deepvk/USER-bge-m3`, ревизия
  `0cc6cfe48e260fb0474c753087a69369e88709ae`, Apache-2.0.

Текущий MVP использует структурированный kNN, поскольку существующий CSV не содержит
фабул для построения dense-индекса. Перед включением Giga проверяется и сохраняется локально
её remote code; `trust_remote_code` без закреплённого проверенного snapshot запрещён.

## Обязательный benchmark

- Одинаковые корпус, временные разбиения, юридические фильтры и слепая разметка; для каждой
  модели — её штатные pooling, нормализация, prefixes и инструкции.
- Индекс и метки ограничиваются данными, фактически доступными на дату прогноза. Все документы
  одного дела исключаются из аналогов запроса.
- Объединённый пул кандидатов всех методов размечается юристом. Пять оценок на запрос дают
  Precision@5, но не обоснованный Recall@20.
- Метрики retrieval: Precision@5, nDCG@10, покрытие эпизодов, p50/p95 latency, peak RAM/VRAM.
  Recall@20 используется только при достаточной полноте эталона.
- Длинные документы разбиваются по эпизодам с контролем покрытия; молчаливое усечение запрещено.
- Закрепляются revisions моделей, версии Transformers/PyTorch/SentenceTransformers, attention
  backend и контрольные выходы inference.

## Определение риска для последующего обучения

Отдельно фиксируются единица наблюдения, горизонт и знаменатель. Состояния «не обжалован»,
«оставлен без изменения», «изменён по основанию, связанному с наказанием» и «исход неизвестен»
не смешиваются. Отсутствие найденной апелляции не является отрицательной меткой. После обучения
требуются временной test, калибровка и сравнение с логистической регрессией и kNN baseline.

## Последствия

До разметки система честно предоставляет формальные проверки, аналоги и наблюдаемые исходы, но
не персональную вероятность пересмотра. Окончательный dense backend выбирается только после
замеров на судебном корпусе и целевом оборудовании.

# Региональные пары по ст. 290 УК РФ

**Уточнение от 09.11.2026:** пользователь разрешил узкое исключение из прежнего локального правила остановки по `robots.txt` для Красноярского, Воронежского и Свердловского судов. Допустимы обычные публичные GET-запросы с паузами не менее 4 секунд; CAPTCHA и отказ в доступе останавливают сбор. Условия и результаты проверки: [collection-2026-11-09.md](collection-2026-11-09.md). Остальной текст ниже сохраняет описание прежнего режима и исторических результатов.

Цель этапа — полные пары «приговор первой инстанции → апелляционный акт» за 2022–2025 годы по дате поступления апелляции.

## Официальные источники

- Красноярский краевой суд: https://kraevoy.krk.sudrf.ru/ и https://kraevoy.krk.sudrf.ru/robots.txt
- Воронежский областной суд: https://oblsud.vrn.sudrf.ru/ и https://oblsud.vrn.sudrf.ru/robots.txt
- Использовалась бы картотека «Уголовные дела — апелляция», поле `Перечень статей=290`, даты поступления.

**Текущее ограничение:** оба robots.txt содержат `Disallow: /*name=sud_delo`. Это закрывает требуемые картотеки, карточки и документы. Поэтому сбор, переходы по карточкам и скачивание текстов не выполняются. Обход, смена параметров и решение CAPTCHA не применяются.

## Команды

Из корня проекта:

```bash
# Проверить robots и сформировать отчёт о доступе.
python tools/regional_courts.py robots --pause 4

# Повторить проверку и, только если robots разрешает пути, выполнить сбор.
python tools/regional_courts.py run --pause 4

# Сформировать публичный отчёт по сохранённым access.json.
python tools/regional_courts.py report
```

Запросы последовательные, с паузой 4 секунды. Сетевая серия из трёх ошибок останавливает сбор; CAPTCHA останавливает немедленно. `checkpoint.json` и атомарная запись позволяют продолжить работу без повторения терминальных кандидатов.

## Правила реализации

- Robots проверяется до картотеки. Запрещённый путь не запрашивается даже для проверки доступности.
- Апелляционные события различаются по суду, ID производства, дате и типу акта, а не только по УИД.
- Тип приговора проверяется по карточке и тексту; мера пресечения и исполнение приговора исключаются.
- Первая инстанция связывается по UID + суду + полному номеру. Региональные номера канонизируются с границами и ведущими нулями, без московских допущений.
- Полная пара требует два полных текста, совпадающие дату и участников. Проверка участников выполняется локально, ФИО в отчёты не выводятся.
- Outcome извлекается только из резолютивной части после маркера, включая разрядку букв; просьбы стороны решением не считаются.
- Файлы и checkpoint содержат SHA256. Извлечённые тексты и исходники хранятся только в `corpus/regional/raw/`.

## Публичные результаты

`report.md` содержит только статусы доступа и агрегаты по суду/году. Прямые URL карточек и актов, номера, УИД, ФИО и хеши конкретных дел не публикуются.

Исторический малый ручной пилот ранее дал по 2 полные пары в каждом суде. Он отделён от текущего автоматического сбора и не экстраполируется на год.

Тесты используют только синтетические HTML, документы и fake transport. Реальные персональные данные и карточки не используются.

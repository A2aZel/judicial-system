# Проверка официальных сайтов судов как источника пар «приговор → апелляция»

**Дата первичной проверки:** 08.11.2026.
**Назначение:** ограниченная разведка источников по ст. 290 УК РФ, а не массовый сбор и не оценка полноты годовой публикации.

## Метод и ограничения

- Встроенный браузер был недоступен: в запуске субагента не включено управление браузером. Использовались `FetchURL`, `WebSearch` и последовательные чтения официальных страниц GET-запросами с паузами не менее 3 секунд.
- На старых сайтах ГАС «Правосудие» страницы декодировались из заявленной кодировки `windows-1251`. Проверялись штатные URL из ссылок и JavaScript самих сайтов; сторонние базы судебных актов не использовались.
- У Мосгорсуда файлы оказались документами старого формата Word (OLE/DOC), а не PDF. Текст проверялся локально через `antiword`; временные файлы удалены.
- Капча не решалась и не обходилась. На Свердловском сайте выполнение поиска остановлено на этом шаге.
- ФИО, персональные данные и фактические обстоятельства конкретных дел не включались. Реальные номера дел, прямые URL карточек и актов, внутренние идентификаторы карточек и хеши из распространяемого отчёта удалены: они позволяют вернуться к конкретным делам и не являются обезличиванием.
- В таблицах используются только внутренние ID просмотра. Оставлены лишь общие формы и поисковые URL.
- **Число записей в поиске не равно числу пар.** В выдачу входят процессуальные апелляции, не у каждой записи есть опубликованный текст, а приговор первой инстанции нужно отдельно найти и проверить.

Дополнительные наблюдения по Мосгорсуду:

## Правила идентичности для последующих проверок

1. **Ключ приговора:** суд первой инстанции, номер дела первой инстанции, дата и тип акта «приговор»; УИД используется как дополнительный ключ только после подтверждения, что он относится к тому же делу. При нескольких участниках соответствие проверяется без записи ФИО в отчёт.
2. **Отдельный ключ апелляционного акта:** апелляционный суд, апелляционный номер, дата и тип конкретного акта. Несколько апелляционных решений на один приговор остаются отдельными событиями даже при совпадении УИД, суда, номера, даты и типа приговора.
3. **Алиасы перенумерации:** номера объединяются только при прямом подтверждении в одной официальной карточке/акте, что они обозначают то же производство и тот же апелляционный акт, с согласующимися датой и типом. Простое соседство старого и нового номера без такого соответствия не считается доказанным алиасом.
4. **Полная пара:** отдельно получены и прочитаны полный приговор и полный соответствующий апелляционный акт; совпадение подтверждено по суду, номеру, дате, типу и, где необходимо, участникам. Карточка или цитата приговора в апелляции полной парой не считается.
5. **Исход хранится отдельно от идентичности:** оставлен без изменения / изменён / отменён / иной или не определён. Наличие мотива изменения не требуется для подтверждения неизменённого приговора.

## Вывод о пригодности

1. **Начинать пилот целесообразно с Красноярского и Воронежского сайтов.** Поиск сужает выдачу по ст. 290 и периоду; первично подтверждены идентификаторы связки и мотивированные апелляционные тексты на приговоры. Получение полных пар этим первичным исследованием не подтверждено.
2. **Мосгорсуд — перспективный, но требующий дополнительной фильтрации источник.** Карточки и DOC-тексты доступны, однако широкая выдача смешивает приговоры с процессуальными решениями. По пяти первым карточкам нельзя оценить долю нужных дел.
3. **Саратовский сайт не даёт целевого фильтра по статье в проверенной форме.** Большой общий объём не помогает без внешнего списка дел по ст. 290.
4. **Свердловский сайт не оценён по содержанию из-за капчи.** Это ограничение доступа, а не вывод об отсутствии апелляций или текстов.

## Следующие шаги

1. Провести отдельный малый пилот полных пар по Красноярскому и Воронежскому сайтам с фиксированными знаменателями: просмотрено записей → исключено → проверено уникальных кандидатов → оба текста найдены → подтверждённые полные пары → осталось непроверенным.
2. Отбирать первые уникальные апелляции именно на приговор независимо от наличия ссылки на текст и исхода. Не заменять отсутствующие тексты более удобными кандидатами после начала проверки.
3. Для каждого кандидата искать приговор на официальном сайте суда первой инстанции по УИД либо по паре «суд + номер первой инстанции»; сверить дату и тип акта с апелляцией.
4. Разделять статусы: не найдено / нет опубликованного текста / ошибка доступа / капча / не проверено / неоднозначное совпадение. Результат малого пилота на годовую выдачу не экстраполировать.
5. По Мосгорсуду проверить небольшую выборку вероятных приговоров не только с первой страницы. Саратов проверять точечно по уже известным номерам/УИД; для Свердловского использовать только ручной или согласованный официальный доступ без решения капчи агентом.
6. Перед включением текстов в общий корпус отдельно проверить обезличивание обоих документов каждой пары. URL и технические хеши хранить только в ограниченном рабочем реестре, не в распространяемых Markdown-отчётах.

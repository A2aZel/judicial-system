# Подготовка пар «приговор → апелляция/кассация»

Рабочий набор формируется из `corpus/regional/raw/collection-2026-11-10/unified-case-index.jsonl` и связанного `metadata.jsonl` для источников `bashkortostan`, `tatarstan` и `novosibirsk`. В processed dataset и processed index записи не добавляются. Результат предназначен для последующей проверки lead.

## Метод

- Единица отбора — запись указанных источников в unified index. Ожидаемые количества проверяются флагом `--strict-counts`.
- `verdict_group_id` строится по официально подтверждённому судебному UID либо по связке суда, полного номера, даты и типа приговора. Производственный UUID UID не считается.
- Апелляционное событие различается по суду, номеру, дате и типу акта. Разные события по одному приговору или UID не дедуплицируются. Дублем считается только повтор той же событийной identity.
- Связывание использует только официальные `first_case` ключи и алиасы из сохранённых метаданных. Новые перенумерации не выводятся алгоритмически.
- `confirmed_pair` возможен только при двух отдельных полных текстах, действительных SHA256 текстов и исходников, совпадающих суде, номере, датах и типах актов. Ссылка, карточка или цитата приговора в апелляции вторым текстом не считаются.
- Процессуальные акты и апелляционные/кассационные приговоры нового рассмотрения отклоняются. Outcome определяется только по резолютивной части после её маркера, а не по доводам сторон.
- Каждый запуск повторно проверяет локальные тексты, исходники и evidence по SHA256. Повреждение исключает подтверждение.

## Доступ и resume

```bash
# Обычный resume: использовать сохранённые access.json и локальные артефакты.
python tools/prepare_bash_tat_nov_pairs.py run --pause 4 --strict-counts

# Повторно проверить robots.txt перед обработкой.
python tools/prepare_bash_tat_nov_pairs.py run --pause 4 --refresh-access --strict-counts

# Пересоздать только агрегированный отчёт из summary.json.
python tools/prepare_bash_tat_nov_pairs.py report
```

Запросы выполняются последовательно, пауза CLI не может быть меньше 4 секунд. Поисковые пути запрещены. При `robots_blocked` карточки и документы не запрашиваются. CAPTCHA немедленно останавливает обработку и не обходится.

Прямые документы используются только при явных `sentence_url`/`appeal_url` в связанных метаданных, разрешённом пути и совпадающем официальном хосте. Они сохраняются в `artifacts/`; повторный запуск использует кеш и не повторяет запрос. Явный `sentence_artifact`/`appeal_artifact` также поддерживается. В текущих исходных метаданных таких ссылок на недостающие тексты нет.

## Файлы

- `pair-status.jsonl` — рабочий реестр с `verdict_group_id`, event identity, путями и SHA артефактов, статусом, outcome и `identity_errors`; может содержать реквизиты дел и не предназначен для публикации.
- `summary.json` — машиночитаемые агрегаты и статус неизменности processed dataset.
- `report.md` — только агрегированные результаты, без персональных данных, номеров, UID, URL и хешей конкретных дел.
- `access.json` и `access/` — состояние доступа и снимки robots.txt.
- `artifacts/` — создаётся только при фактической загрузке разрешённых прямых документов; в текущем прогоне не создавался.

`missing_sentence`/`missing_appeal` означает отсутствие пригодного локального второго текста, а не доказательство отсутствия судебного акта. Outcome уже скачанных апелляционных текстов отдельно от outcome подтверждённых пар.

```bash
python -m pytest tests/test_prepare_bash_tat_nov_pairs.py tests/test_regional_courts.py -q
```

Тесты синтетические: полная пара, SHA и identity, процессуальные акты, новый приговор, дубли и разные события с одним UID, запреты доступа, CAPTCHA и resume кеша.

# Полные пары приговор — апелляция

Локальный рабочий набор для 288 дел по ст. 290 УК РФ из шести источников единого индекса. Это не processed dataset: включение в обучение требует отдельной проверки lead.

## Запуск

Из корня проекта:

```bash
PYTHONIOENCODING=utf-8 python -m tools.pair_preparation
```

По умолчанию используются только уже скачанные документы. Для отсутствующих апелляций с единственной прямой ссылкой официального open data:

```bash
PYTHONIOENCODING=utf-8 python -m tools.pair_preparation --download
```

Сетевой режим последовательный, с паузой 4 секунды после каждого запроса. Разрешены только HTTPS URL `mos-gorsud.ru` и `data.mos-gorsud.ru` с путём `/mgs/cases/docs/content/`. Поисковые endpoint, сторонние redirect, CAPTCHA и access denial запрещены; отказ доступа немедленно прерывает обработку. Новые файлы сохраняются только в `raw/texts/` этого каталога.

Проверки:

```bash
PYTHONIOENCODING=utf-8 python -m pytest -q tests/test_pair_preparation.py
```

## Метод

- Индекс группируется по `underlying_case_id`; исходные 288 дел не отождествляются с числом подтверждённых пар. Несколько апелляционных событий одного приговора остаются отдельными строками.
- Официальные кандидаты с двумя текстами, которых нет в сводном индексе, проверяются дополнительно. В итог добавляются только независимо подтверждённые пары; событие, уже представленное в индексе теми же SHA приговора и апелляции, повторно не добавляется.
- Старые `existing_confirmed` и `confirmed_pair` не считаются доказательством. Оба текста проверяются заново, включая SHA256 текста и исходного файла, если исходный файл указан в индексе.
- Для официальных московских данных используется строгий `verify_pair`: УИД, суд, номер и дата приговора, реквизиты апелляции, тип акта и резолютивная часть. Номер приговора должен подтверждаться текстом приговора; отсутствие ссылки на номер в апелляции допустимо, конфликт — нет. У приговора проверяются мотивировочная часть (`установил`) и резолютивная часть: сокращённый текст без мотивировки не принимается.
- Алиасы принимаются только из официальных записей и только при совпадающих непустых дате и типе акта. Региональный адаптер проверяет аналогичные реквизиты без применения московских правил к другим судам.
- Процессуальные определения, акты без подтверждённой резолютивной части и направления на новое рассмотрение не становятся полными парами. Дата нового приговора после даты апелляции также исключается.
- `verdict_group_id` вычисляется по нормализованному тексту приговора и каноническим суду, номеру, дате и типу. Источник, пробелы, OCR-разрывы и точные байты файла не влияют на группу. `case_id` дополнительно различает апелляционное событие.
- Для retrieval выбирается не более одной подтверждённой записи на `verdict_group_id`; это не удаляет отдельные апелляционные события из статусного файла.
- Для источника `recovery` используется приговор, адресованный единым индексом. Его отдельный raw-pipeline и кандидаты не запускаются.

## Артефакты и resume

- `raw/pair-status.jsonl` — закрытый рабочий файл: хешированные `case_id` и `verdict_group_id`, источник, год, тип, пути и SHA артефактов, статус, outcome и ошибки identity. Может содержать чувствительные пути; не публиковать.
- `raw/pair-progress.json` — атомарно обновляемое состояние после каждого события. Повторный запуск использует fingerprint входа и заново проверяет SHA сохранённых артефактов. Изменение или удаление файла отменяет resume для соответствующей записи.
- `raw/texts/` — только артефакты, скачанные разрешённым сетевым режимом.
- `report.md` — исключительно агрегаты по источнику, году, типу, статусу и outcome; без ФИО, номеров дел, УИД, URL и хешей конкретных дел.

Переход offline → `--download` повторяет только отсутствующие или неудачно скачанные прямые вложения. Обратный переход не удаляет и не заменяет уже проверенные скачанные артефакты. Для полного независимого пересчёта используйте новый `--output`; существующий processed dataset и dense index команды не изменяют.

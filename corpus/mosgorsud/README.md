# Московские открытые данные по ст. 290 УК РФ

Конвейер использует только официальный портал открытых данных Мосгорсуда и прямые ссылки на документы из его наборов. Поисковые страницы `mos-gorsud.ru/mgs/search` и любые URL с `/search` не запрашиваются.

## Источники и условия

- Портал: https://data.mos-gorsud.ru/opendata
- Условия использования: https://data.mos-gorsud.ru/terms-of-use. Копирование и адаптация разрешены без отдельного соглашения; при использовании указываются URL источника и дата обновления набора.
- Апелляционные уголовные дела: https://data.mos-gorsud.ru/opendata/1577117758402-casesgroupmgsappealcriminalquiik
  API: https://data.mos-gorsud.ru/api/opendata/1577117758402-casesgroupmgsappealcriminalquiik/v287/data/json
  Дата обновления набора: **2026-11-08**.
- Уголовные дела первой инстанции: https://data.mos-gorsud.ru/opendata/1577116724824-casesgroupfirstcriminalluivn
  API: https://data.mos-gorsud.ru/api/opendata/1577116724824-casesgroupfirstcriminalluivn/v287/data/json
  Дата обновления набора: **2026-11-08**. Точный идентификатор получен через официальный реестр `/api/opendata/?topicId=5293e9ae-6b3f-11e9-a923-1681be663d3e`.

`raw/datasets.json` хранит URL, дату набора, размер и SHA256 каждого ZIP. Валидный ZIP повторно не скачивается. Файл сначала пишется в `.part`, проверяется и атомарно переименовывается; частичная загрузка продолжается через HTTP Range, если сервер её поддерживает. При HTTP-ошибке или капче загрузка прекращается.

## Возобновляемый запуск

Из корня проекта:

```bash
# Необязательно, если оба ZIP уже проверены.
python tools/mosgorsud_open_data.py download --dataset appeals
python tools/mosgorsud_open_data.py download --dataset first

# Полный потоковый разбор и агрегированный отчёт без скачивания текстов.
python tools/mosgorsud_open_data.py analyze

# Небольшой блок текстов; повторный вызов продолжает с checkpoint.
python tools/mosgorsud_open_data.py download-texts --limit 10 --pause 4

# Весь остаток до исчерпания кандидатов или сетевой блокировки.
python tools/mosgorsud_open_data.py download-texts --limit 0 --pause 4

# Эквивалентный resume: проверить первый ZIP, разобрать данные и продолжить тексты.
python tools/mosgorsud_open_data.py run --limit 10 --pause 4

# Только проверка/обновление агрегатов без новых документов.
python tools/mosgorsud_open_data.py run --limit 0
```

По умолчанию пауза перед каждым сетевым запросом — 4 секунды. Ранее зафиксированные HTTP-ошибки и капча не повторяются автоматически. Осознанный повтор возможен только отдельной командой:

```bash
python tools/mosgorsud_open_data.py download-texts --limit 1 --retry-errors
```

## Правила разбора

- Корневой JSON — массив. Он читается потоково непосредственно из ZIP, без распаковки ~397 MB в память и без сторонних зависимостей.
- Статья определяется только по `participants[].codexArticles[].name`, с точным различием 290, 290.1 и 1290.
- В период включается запись, если 2022–2025 встречается хотя бы в одном измерении: год номера, год поступления или год апелляционного акта. В `report.md` эти измерения показаны отдельно и не суммируются.
- Кандидатский фильтр использует исходные префиксы уголовных дел `1-` и `01-`. Кандидат ещё не считается апелляцией на приговор: процессуальные записи отсекаются при проверке текста.
- Апелляционные события не дедуплицируются по УИД. Отдельно хранятся `_id`, номер/год, дата и тип события. Перенумерация сохраняется и используется как алиас только при фактически совпадающих непустых дате/типе; отсутствующие поля совпадением не считаются.
- Первая инстанция связывается по УИД + суду + номеру. Несколько разных актов при том же УИД различаются номером и датой; неоднозначная связка не подтверждается.
- Полные номера извлекаются с границами и канонизируются по префиксу, последовательности и году. Проверка не использует substring: например, `1-1/2024` и `1-11/2024` различаются. Номер первой инстанции обязателен в самом приговоре. В апелляции его присутствие подтверждает связь, но отсутствие не является ошибкой: datasets уже связаны по UID+court+number и проверяются остальные реквизиты. Явная распознанная ссылка на обжалуемый приговор с другим номером даёт `sentence_number_conflict`; производственный номер апелляции конфликтом не считается. Несколько противоречивых ссылок дают `manual_review`, без отклонения по одному неразличимому номеру. Суд проверяется в обоих документах. Метаданные дат приговора и апелляции обязательны: отсутствие или непарсируемость исключает подтверждение. Между текстами должна совпадать одна конкретная дата приговора, а не независимые даты из списка.
- При нескольких attachments полностью перебираются все допустимые комбинации без числового cap. Дата приговора позже апелляции делает комбинацию несовместимой; подходящий акт после 16-й комбинации не пропускается, несовместимые документы не смешиваются. При отсутствии допустимой комбинации ставится терминальный `no_compatible_attachment`.
- Скачивание начинается после формирования воронки. Каждый документ и каждый результат записываются атомарно в checkpoint.
- Транспорт проверяет `Content-Length` и `Content-Range` перед успешным EOF. Неполный документ не принимается. Ошибки во время `response.read()` становятся `DownloadError` с checkpoint; обычный resume не повторяет их без `--retry-errors`. ZIP дополнительно проходит CRC.
- Range-resume привязан только к ETag/Last-Modified и `If-Range`; Content-Location/URL валидатором не считается. Без надёжного валидатора начинается чистая загрузка, смена ресурса не склеивается со старым `.part`. HTTP 416 принимает полный `.part` только при совпадающих размере и версии, иначе безопасно перезапускает загрузку.
- HTTP 404 сохраняется на конкретном кандидате, и сбор продолжается со следующего. CAPTCHA останавливает немедленно, включая SmartCaptcha в теле HTTPError 403/429 с ограниченным безопасным чтением; серия из трёх последовательных не-404 сетевых ошибок останавливает после checkpoint. Сохранённые ошибки не повторяются без `--retry-errors`.
- Для каждого документа хранятся SHA256 бинарника, SHA256 текста и `text_source_sha256`. Изменение бинарника требует нового извлечения. `analyze` проверяет наличие и хеши обоих исходников и текстов; повреждение снимает подтверждение (`artifact_invalid`) и возвращает запись в resume.
- DOC/OLE извлекается установленным `antiword`; PDF — уже установленным `pypdf`, DOCX — stdlib. Неподдерживаемый формат получает явный статус.
- `both_files_downloaded`, `both_texts_extracted` и `confirmed_pair` — разные статусы. Наличие двух бинарников не означает извлечённые тексты, а извлечённые тексты не гарантируют идентичность. `unsupported_format` терминален, сохраняется при revalidate и не включается в «не начато».
- Полная пара засчитывается после фактического получения двух файлов, извлечения ненулевого текста, проверки номеров/дат/суда и типа акта. Для апелляции требуется резолютивное действие именно над приговором, а не упоминание приговора или отмена процессуального постановления.
- Резолютивная часть обязательна и начинается строго после маркера, включая разрядку `П О С Т А Н О В И Л`: без маркера outcome равен `unknown`, а `has_sentence_operative=False`. Просьбы стороны до маркера решением не считаются; отсутствие решения после маркера также даёт `unknown`. Процессуальный срок обжалования/восстановления исключается, но законное изменение назначенного срока наказания допускается.
- Формальный `outcome` (`unchanged` / `changed` / `cancelled` / `unknown`) извлекается только из резолютивной части и публикуется отдельно для подтверждённых пар и для остальных проверенных записей. Он не используется как доказательство идентичности.
- При изменении правил проверки уже сохранённые пары и артефакты повторно валидируются при `analyze`. Сравнение с историей добавляется только при наличии фактического предыдущего `analysis.json`; первый запуск истории не выдумывает.

## Каталоги и приватность

- `raw/*.zip` — официальные исходные наборы.
- `raw/datasets.json` — технические метаданные источников.
- `raw/work/` — кандидаты и агрегированный анализ.
- `raw/texts/` — исходные документы и извлечённые тексты.
- `raw/pair-progress.json` — checkpoint по каждому документу и паре, включая URL и хеши.
- `report.md` — только агрегаты по годам и статусам.

В `raw` присутствуют персональные данные, номера, УИД и прямые URL. Каталог предназначен только для локальной работы: не отправлять наружу и не коммитить. `report.md` не содержит ФИО, номеров, УИД, прямых карточек/актов или хешей конкретных дел.
